# anime-renamer

[Annict](https://annict.com/) のデータをもとに、テレビ録画ファイルを `<作品名> #<話数> 「<サブタイトル>」.<元の拡張子>` の形式に自動でリネームするCLIツールです。

## 特徴

- ファイル名から作品名・話数・サブタイトル・録画日時を解析
- Annict APIで作品・エピソード・放送履歴を検索し、ファイルと照合
- 話数がない場合、しょぼいカレンダーの放送履歴から一意に証明できた話数だけを補完
- 作品名の全角/半角・句読点の表記ゆれ、話数表記(`ep.7` / `第7話` / `第七話` / `#7` / `1ふさ目` / `home.02` など)の違いを吸収。「メダリスト」の `score06` と「夜桜さんちの大作戦」の `作戦40` にも対応
- マッチングの信頼度をスコアリングし、閾値未満は自動リネームせず確認を促す
- 明示された小数話（`#3.5` / `第13.5話` など）を整数に丸めず照合・出力
- 話数を特定できない特番・複数話結合・第0話は理由を表示して安全にスキップ
- 検索結果をローカルにキャッシュしてAPI呼び出しを削減
- `--dry-run` でリネーム内容を実行前に確認可能
- Annictとの照合結果を動画へ埋め込み、またはJellyfin用NFOとして保存（任意）
- `--metadata-only` でリネーム済みの動画へメタデータだけを後付け

## インストール

### Releaseから取得

[Releases](https://github.com/yude/anime-renamer/releases) ページから、お使いのOS向けのビルド済みバイナリ(Linux/macOS/Windows, amd64/arm64)をダウンロードしてください。

### ソースからビルド

Go 1.26.5以降が必要です。

```sh
git clone https://github.com/yude/anime-renamer.git
cd anime-renamer
go build -o anime-renamer .
```

### go installでインストール・更新

リリース前の改善も含めて更新する場合は、`master` ブランチを指定します（Go 1.26.5以降が必要）。

```sh
go install github.com/yude/anime-renamer@master
```

配置先は `GOBIN`、未設定なら `$(go env GOPATH)/bin` です。rootで `/usr/local/bin` に配置する場合は、`GOBIN=/usr/local/bin go install github.com/yude/anime-renamer@master` を実行してください。`@latest` は最新のリリースタグを優先するため、リリース前の変更が含まれないことがあります。

## 使い方

Annictの[アクセストークン](https://annict.com/settings/apps)を環境変数 `ANNICT_ACCESS_TOKEN` に設定するか、対象ファイル/ディレクトリと同じ場所(またはその親ディレクトリ)に `.env` ファイルを置いてください。

```sh
export ANNICT_ACCESS_TOKEN=xxxxxxxxxxxxxxxx
```

`.env` ファイルの例:

```
ANNICT_ACCESS_TOKEN=xxxxxxxxxxxxxxxx
```

### 基本的な使い方

```sh
# 1ファイルをドライラン(実際にはリネームしない)
anime-renamer --dry-run "花ざかりの君たちへ 第2期 ep．7「ずっとそばにいたいから」 (20260813).mp4"

# ディレクトリ内のファイルをまとめて処理(サブディレクトリも含める)
anime-renamer --dry-run --recursive /recordings/

# 実際にリネームを実行
anime-renamer /recordings/
```

### オプション

| オプション | 説明 |
| --- | --- |
| `--dry-run` | リネームを実行せず、プレビューのみ表示する |
| `--recursive` | サブディレクトリも再帰的に処理する |
| `--verbose` | Annict側の詳細情報(作品・エピソード・放送情報)を表示する |
| `--no-cache` | ローカルキャッシュを使用しない |
| `--confidence` | 自動リネームに必要な最低信頼度(0〜100)。省略時は通常実行・`--dry-run` ともに90 |
| `--output` | 出力先ディレクトリ(省略時は入力ファイルと同じ場所) |
| `--epgstation-url` | 日付のみの録画を補完するEPGStationのURL。環境変数または `.env` の `EPGSTATION_URL` でも設定可能 |
| `--ts-metadata` | `.ts` / `.m2ts` 内の放送番組情報を照合に使う。既定で有効。`--ts-metadata=false` で無効化 |
| `--metadata` | `none`（既定）、`auto`、`embedded`、`nfo`。`auto` はMP4/M4V/MKVに埋め込み、TS/M2TSはNFOを生成 |
| `--metadata-only` | 動画名と配置を維持してメタデータだけを追加。`--metadata` 省略時は `auto`。`--output` との併用不可 |
| `--metadata-season` | Annict作品ごとのローカルなシーズン番号（既定 `1`）。作品名の「第2期」などから推測しない |
| `--keep-backup` | 埋め込み成功後も元動画のバックアップを保持。省略時は検証・置き換え・同期の成功後に削除 |
| `--metadata-timeout` | 動画1本の埋め込み・検証に使える時間（既定 `30m`）。大きい録画や低速ストレージでは `2h` などを指定 |

対応する拡張子は `.mp4` `.ts` `.m2ts` `.mkv` `.m4v` です。

### Jellyfin用のメタデータ

動画へ埋め込める形式を優先する場合は `--metadata auto` を指定します。従来のコマンドは既定でメタデータを書き込まないため、動画そのものを変更する処理は明示的に選べます。

```sh
# 新しい録画: リネームとメタデータ付与をプレビュー
anime-renamer --metadata auto --dry-run --recursive /mnt/prod/recorded

# 実行: 作品ごとのディレクトリへリネームし、メタデータを付与
anime-renamer --metadata auto --recursive /mnt/prod/recorded

# 既にリネーム済みの動画: 名前と配置を変えず、メタデータだけを追加
anime-renamer --metadata-only --dry-run --recursive /path/to/organized
anime-renamer --metadata-only --recursive /path/to/organized

# 動画のバイト列を変更せず、全形式でNFOを使う場合
anime-renamer --metadata-only --metadata nfo --recursive /path/to/organized
```

作品名・サブタイトル・明示話数・Annict IDを保存します。書き込みには通常の厳密な照合に加えて信頼度90以上と、Annict上の正の整数話数・エピソードIDを要求します。`--confidence` を下げてもメタデータの条件は緩めません。小数話や番号未確認の特番は、Jellyfin用の整数に丸めたり独自番号を割り当てたりせずスキップします。再放送を含む録画日を、そのエピソードの初回放送日として保存することはありません。

**動画への埋め込み:** MP4/M4V/MKVで `ffmpeg` と `ffprobe` が必要です。`title`、`show` / `show_name`、`season_number`、`episode_sort` を保存し、標準のコメント欄にAnnictのURLを追記します。既存の他のメタデータを引き継ぎ、映像・音声・字幕などは `-c copy` でコピーします。再エンコードはしません。同じディレクトリの一時ファイルへリマックスし、ストリーム構成、チャプター、エンコード済みパケットの内容・ヘッダー・時刻を検証してから置き換えます。

Nero形式のチャプターだけを持つMP4では、FFmpegがQuickTime形式のチャプター用補助トラックを追加することがあります。MP4内で実際にチャプター用として参照されている追加トラック1本だけを許容し、元からある全ストリームは引き続き検証します。チャプターは時刻の単位を換算して比較し、開始位置・タイトル・途中の終了位置が一致することを要求します。元のNero形式で動画の長さから算出される最終チャプターの終了位置に限り、補助トラックの1目盛り以内（最大1ミリ秒）の丸めを許容します。映像・音声・字幕のパケット時刻はこの例外の対象になりません。

HEVCのMP4では、FFmpeg 7以降が初期化ヘッダー（`hvcC`）の `parallelismType` を0へ正規化する場合があります。`min_spatial_segmentation_idc=0` で、残りのヘッダーとVPS/SPS/PPSが完全に同じ場合に限り、一時MP4の当該バイトを元の値へ戻します。その後、ヘッダー・全パケット・時刻を通常どおり完全一致で検証します。対象はトラックIDから特定した単一のHEVCサンプル記述に限定し、ほかのヘッダー変更や曖昧な構造はNFOへの切り替え／エラーとして扱います。

置き換えの直前に、動画の隣の `.anime-renamer-backups/<ファイル名のSHA256>.original` へ復旧用バックアップを作成します。**既定では、検証・置き換え・ディレクトリ同期の成功後にバックアップを削除し、空になったバックアップディレクトリも削除します。** 成功後も残す場合だけ `--keep-backup` を指定してください。置き換えや同期に失敗した場合はバックアップを保持し、エラーに復旧先を表示します。既存のバックアップは上書きしません。

同じメタデータで再実行した場合、動画は書き換えません。旧版や中断した処理のバックアップが残っていれば、元動画の全ストリーム・チャプター・パケットを現在の動画と再検証し、一致したものだけ削除します（`--keep-backup` 指定時は保持）。破損・不一致・検証不能のバックアップは残してエラーにします。異なるメタデータへ更新する際に既存バックアップがある場合は、自動的に削除せず処理を止めます。復元するときは、関連する処理を停止し、表示されたバックアップを元の動画パスへコピーしてください。

埋め込みには動画全体の読み書きと検証、および元動画を保持するための空き容量が必要です。Linux/macOSでは所有者・権限・拡張属性（POSIX ACLを含む）と更新日時を引き継ぎ、保持できなければ置き換え前に停止します。同じ動画への埋め込みはOSのファイルロックで排他し、正常終了時にロックファイルを削除します。強制終了で残ったロックファイルは、次の実行で再利用できます。ファイルロックやディレクトリ同期に対応しないファイルシステムではエラーとして扱います（Windowsではディレクトリ同期の保証が異なります）。

`Ctrl+C` / `SIGTERM` は外部コマンドとAPI待ちを中断し、残りの動画を処理せず終了します。強制終了・電源断では一時ファイルや復旧用バックアップが残る場合があります。別の録画・変換・移動処理と同時に同じ動画を変更しないでください。リネームとメタデータの付与は個別の処理なので、付与に失敗した時点で動画が移動済みの場合は、そのパスをエラーに表示します。dry-runは読み取りによる事前確認までを行い、実際のリマックス・パケット検証は書き込み時に行います。

**NFOとフォールバック:** TS/M2TSへは同じ形式のエピソードタグを保存できないため、動画と同じベース名の `.nfo` を生成します。`auto` では埋め込み時にストリーム・字幕ヘッダー・チャプターなどを維持できないと判定した場合も、動画を保持してNFOに切り替えます。`embedded` を明示した場合はNFOへ切り替えず失敗を報告します。全てNFOに統一したい場合は `--metadata nfo` を使います。

既存のNFOは内容を変えません。動画の名前・配置を変えずに埋め込む場合は、既存NFOが今回生成するNFOと完全に一致するときだけ、保持したまま埋め込みを再試行できます。以前のフォールバックで生成されたNFOもこの条件で扱います。手動編集されたNFO、異なるメタデータを持つNFO、リネームで動画と離れてしまうNFOは、手動確認が必要なものとしてスキップします（NFOがJellyfinで優先されるためです）。NFOだけを後付けするモードでは、既存NFOを保持して不足分だけを作成します。`tvshow.nfo` は作品ごとに整理されたフォルダにだけ生成し、複数作品が混在する入力ディレクトリには作成しません。

**シーズンとJellyfinへの反映:** 現在の出力構成に合わせ、Annictの各作品をそれぞれ独立した作品フォルダ・ローカルのシーズン1として扱います。Annictの「第2期」を別データベースのシーズン2へ自動換算しません。既存の構成に合わせる必要がある場合は、作品単位で `--metadata-season 2` などを指定してください。これだけで異なるAnnict作品のフォルダを1作品へ統合することはありません。

Jellyfinでは対象ライブラリの「埋め込みタイトルを優先」「埋め込みエピソード情報を優先」を有効にし、対象作品のメタデータを更新してください。既に付いている誤った話数は、埋め込み情報を優先して再取得する必要があります。動画の更新日時は保持するため、通常のファイル監視による自動反映には依存しません。NFOも対象作品のメタデータ更新で読み込ませます。CLIからJellyfinの設定変更やライブラリ全体のスキャンは実行しません。

形式は [JellyfinのNFO仕様](https://jellyfin.org/docs/general/server/metadata/nfo/) と [Jellyfin 10.11.7の埋め込みタグ読み取り](https://github.com/jellyfin/jellyfin/blob/v10.11.7/MediaBrowser.MediaEncoding/Probing/ProbeResultNormalizer.cs) に合わせています。あらすじ・画像・キャストの追加取得や、Annictにない情報の補完は行いません。

### リネーム後のファイル名

```
<出力先>/<作品名>/<作品名> #<話数> 「<サブタイトル>」.<元の拡張子>
```

元ファイルのコンテナ形式は変換せず、拡張子をそのまま維持します。Annict側にサブタイトルが登録されていない場合は、ファイル名から解析したサブタイトルを使用します。ファイルシステムで使用できない文字(`/ \ : * ? " < > |`)は全角の類似文字に置き換えられます。

話数を一意に決められない結合録画(` #01,02 `など)はスキップします。小数話は独立したラベルとして扱い、Annictの明示的な話数表記・数値と一意に一致し、字幕全体も一致する場合だけ `#13.5` のように出力します。字幕がない未確認の小数話は保留します。Annict内部の数値が `13` でも公開表記が `第13.5話` なら、小数表記を保持し、通常の第13話としては照合しません。小数話を整数へ丸めたり、複数話の先頭だけを採用したりしません。

話数のない未確認の特番・総集編や第0話はスキップし、処理結果の`Skipped`に集計します。通常回らしいファイルに作品名と録画日だけがある場合は、Annictの`syobocalTid`を使ってしょぼいカレンダーの放送履歴を照合します。同じ日に得られた有効な候補がすべて同じ正整数話数を示し、その話数とサブタイトルがAnnictのちょうど1エピソードに対応するときだけリネームします。

字幕の個別補正は作品・明示話数・字幕全体の組に限定しています。「テムパル」第1話の「レジェンダリー職業／レジェンダリー転職」と、「もっとらぶらぶ作戦です！」第4話の「ミニぺパ／ミニペパ」を含む複合字幕に対応しています。他の作品・話数へ同じ置換を広げません。

話数がなくサブタイトルだけがある録画は、従来どおりサブタイトル全体で一意に決まる場合を先に照合します。それで決まらないときだけ録画日を使い、Annictの同名・明示的な続編候補ごとにしょぼいカレンダーを確認します。`/`または`／`で区切られた公式複合サブタイトルの完全な要素（または明示的な「ほか」省略）と一致し、放送話数も含めて成功する作品がちょうど1件で、未確認候補が残らない場合だけリネームします。単なる部分文字列、前編・後編の相違、API失敗、複数作品での成立はスキップします。

録画日があり、話数・サブタイトル・最終回指定のない `セレクション放送` / `セレクション再放送` は、末尾の放送枠名を除いて同じ厳密な日付照合を行います。選抜順から元の話数を推測しません。「ワールド イズ ダンシング」の `[終] 留〆` は話数に変換せず、サブタイトルでAnnictのエピソードを一意に確認します。

Annictの第2クール以降に `syobocalTid` が未登録でも、元作品と明示的なクール続編のエピソード一覧が全件揃い、話数が重複せず、元作品の放送表と話数・サブタイトル全体が一致する場合だけ補完します。別のシーズンや独立した放送表を持つ作品、字幕欠落、警告付きの放送行しかない場合には、この補完を使いません。

複数局で話数が異なる場合は、同じ処理対象に含まれる「録画日と明示話数があるファイル」を放送局アンカーとして使います。異なる録画日のアンカーが2件以上同じチャンネルを一意に示し、別チャンネルを示すアンカーが1件もない場合だけ、そのチャンネルに絞って日付のみの録画を判定します。アンカー不足や矛盾があれば推測せずスキップします。処理順への依存を避け、明示話数のファイルに宛先の優先権を与えるため、バッチ内では日付のみの候補を最後に処理します。

この照合では `https://cal.syoboi.jp/db.php` の `ProgLookup` を使用します。サービスの仕様に従って固有User-Agentを送信し、リクエスト間隔を1秒以上空け、結果を既定で7日間ローカルキャッシュします。`--no-cache`指定時はこのキャッシュも無効になります。

### TS・M2TS内の放送番組情報

`.ts` / `.m2ts` には、映像・音声とともに番組表情報（EIT）が残っていることがあります。既定で録画ファイルの最大3か所を合計最大24 MiBだけ読み取り、番組名・話数・サブタイトル・放送局・放送日時を補助情報として使います。188 / 192 / 204バイトのTSパケットに対応し、`ffprobe` などの外部コマンドは必要ありません。

番組表には別サービスや次の番組も含まれるため、PAT/PMTが示す単一サービスと実在する映像PID、同じTS・ネットワークのSDT、現在番組のEIT（actual present、section 0）、番組の時間内を示すTDT/TOTを組み合わせます。複数のサンプルが同じ番組を示す場合だけ採用します。SIセクションのCRC・連続性を検査し、日本語はARIB文字コードとして復元します。未対応の文字や外字は推測して置換しません。

ファイル名にない情報だけを補い、作品・話数（小数を含む）・字幕・録画日が食い違う場合はスキップします。EITに明示話数と字幕全体がある場合も、Annict上の同じ作品の話数・字幕と一意に一致することを要求します。それだけでは確定しない場合は、復元した放送局と番組開始・終了時刻に一致する、警告のないしょぼいカレンダーの放送行も照合します。番組表のあらすじに登場する任意の話数は拾いません。

番組情報が残っていない録画、必要な情報が揃わない録画は、従来のファイル名・日付・EPGStationの照合に戻ります。複数番組・複数サービスと確認できた録画はスキップします。MP4などにはこの処理を行いません。録画ファイルは読み取りだけで、映像・音声・メタデータを書き換えません。リネームする前に `--dry-run` で確認できます。

```sh
anime-renamer --dry-run "作品名 (20261112).m2ts"
# TSの番組情報を使わず、従来の照合だけで処理する場合
anime-renamer --ts-metadata=false --dry-run /recordings/
```

参考：[ARIB STD-B10（番組情報・放送時計）](https://www.arib.or.jp/english/html/overview/doc/6-STD-B10v5_13-E1.pdf)、[ARIB STD-B24（文字コード）](https://www.arib.or.jp/english/html/overview/doc/6-STD-B24v5_2-1p3-E1.pdf)。

### EPGStationの録画履歴による補完

通常の日付照合で確定できない「作品名と録画日だけ」のファイルは、EPGStationに残る録画情報で放送局と時刻を補えます。任意の機能で、URLを設定した場合だけ利用します。

```sh
anime-renamer --dry-run --epgstation-url http://epgstation:8888 /recordings/

# 環境変数、または対象ディレクトリ・親ディレクトリの .env でも設定可能
export EPGSTATION_URL=http://epgstation:8888
anime-renamer --dry-run /recordings/
```

EPGStationから取得するのは `/api/recorded` と `/api/channels` の情報のみです。元ファイル名全体（拡張子を除く）と録画日が一致する履歴がちょうど1件ある場合だけ使います。`.m2ts` を `.mp4` に変換した録画にも対応しますが、作品名や日付だけが似た履歴、元ファイル名が変更済みの履歴からは推測しません。録画中・エンコード中、履歴の重複、途中ページの取得失敗も補完を停止します。検索結果と放送局一覧は実行中だけ保持し、EPGStation上の録画・設定・ファイルは変更しません。

取得した放送局名をしょぼいカレンダーの `ChLookup` と照合し、開始・終了時刻も一致する放送行に絞ります。番組説明の先頭に `第4話` / `Chapter.6` / `#6` などがあれば、その話数も放送表と照合し、字幕があればAnnictとの一致を求めます。あらすじ中に出てくる話数は採用しません。警告付き放送行は、EPGStationの明示話数・字幕でも裏付けられる場合だけ使用します。Annict側の作品・話数・字幕が一意に決まらない場合は、従来どおりスキップします。

### 確認済みの特別番組・単独映画

Annictに各話データがない場合でも、公式に告知された作品・放送局・放送開始日時と、確認済みのEPGStation録画枠の開始終了時刻・元ファイル名を組み合わせて、限定した番組だけを補完できます。現在の対象は次の2件です。

- 「マウスカーソルで現実を操作できるようになったので、女の子をいっぱいクリックしまーす」の2026年10月26日1:00～1:05、BS11放送分。EPGStationの専用の「番組内容」欄全体が `#3.5` であることも確認し、`#3.5 「オーディオコメンタリー」` と出力します。一般のあらすじ・出演者・お知らせ欄からは話数を拾いません。[公式の特番告知](https://maukuri.af-original.com/news/817/)
- 「死亡遊戯で飯を食う。 44:CLOUDY BEACH」の2026年9月28日23:30～翌1:00、BS日テレ放送分。Annictの映画区分も確認し、`<作品名>/<作品名>.<元の拡張子>` と出力します。作品名中の `44` を話数に変換せず、架空の第1話も作りません。[公式の放送情報](https://shiboyugi-anime.com/theater/)

これらは確認済みの放送枠に限定した補完です。別作品・別日・別局・時刻違い、内容欄の話数の矛盾はスキップします。Annictに登録がない特番全般を自動で通す機能ではありません。

## 仕組み

1. ファイル名を解析し、作品名・話数・サブタイトル・録画日時を抽出
2. Annict APIで作品名を検索
3. 該当する作品が複数見つかった場合、放送シーズン・話数などで絞り込み
4. 話数・サブタイトル・放送日時の一致度からマッチングの信頼度を算出
5. 話数がない通常回はしょぼいカレンダーの放送履歴とAnnictエピソードが一意に一致するか検証し、必要なら同じバッチの2件以上の一貫した放送局アンカーで絞り込み
6. 信頼度が閾値以上であればリネームを実行(閾値未満や一意に決まらないものはリネームしない)
