# anime-renamer

[Annict](https://annict.com/) のデータをもとに、テレビ録画ファイルを `<作品名> #<話数> 「<サブタイトル>」.<元の拡張子>` の形式に自動でリネームするCLIツールです。

## 特徴

- ファイル名から作品名・話数・サブタイトル・録画日時を解析
- Annict APIで作品・エピソード・放送履歴を検索し、ファイルと照合
- 話数がない場合、しょぼいカレンダーの放送履歴から一意に証明できた話数だけを補完
- 作品名の全角/半角・句読点の表記ゆれ、話数表記(`ep.7` / `第7話` / `第七話` / `#7` / `1ふさ目` / `home.02` など)の違いを吸収。「メダリスト」の `score06` と「夜桜さんちの大作戦」の `作戦40` にも対応
- マッチングの信頼度をスコアリングし、閾値未満は自動リネームせず確認を促す
- 単一の正整数話数にできない特番・複数話結合・小数話・第0話は理由を表示して安全にスキップ
- 検索結果をローカルにキャッシュしてAPI呼び出しを削減
- `--dry-run` でリネーム内容を実行前に確認可能

## インストール

### Releaseから取得

[Releases](https://github.com/yude/anime-renamer/releases) ページから、お使いのOS向けのビルド済みバイナリ(Linux/macOS/Windows, amd64/arm64)をダウンロードしてください。

### ソースからビルド

Go 1.26.5以降が必要です。

```sh
git clone https://github.com/yude/anime-renamer.git
cd anime-renamer
go build -o anime-renamer .
```

### go installでインストール・更新

リリース前の改善も含めて更新する場合は、`master` ブランチを指定します（Go 1.26.5以降が必要）。

```sh
go install github.com/yude/anime-renamer@master
```

配置先は `GOBIN`、未設定なら `$(go env GOPATH)/bin` です。rootで `/usr/local/bin` に配置する場合は、`GOBIN=/usr/local/bin go install github.com/yude/anime-renamer@master` を実行してください。`@latest` は最新のリリースタグを優先するため、リリース前の変更が含まれないことがあります。

## 使い方

Annictの[アクセストークン](https://annict.com/settings/apps)を環境変数 `ANNICT_ACCESS_TOKEN` に設定するか、対象ファイル/ディレクトリと同じ場所(またはその親ディレクトリ)に `.env` ファイルを置いてください。

```sh
export ANNICT_ACCESS_TOKEN=xxxxxxxxxxxxxxxx
```

`.env` ファイルの例:

```
ANNICT_ACCESS_TOKEN=xxxxxxxxxxxxxxxx
```

### 基本的な使い方

```sh
# 1ファイルをドライラン(実際にはリネームしない)
anime-renamer --dry-run "花ざかりの君たちへ 第2期 ep．7「ずっとそばにいたいから」 (20260813).mp4"

# ディレクトリ内のファイルをまとめて処理(サブディレクトリも含める)
anime-renamer --dry-run --recursive /recordings/

# 実際にリネームを実行
anime-renamer /recordings/
```

### オプション

| オプション | 説明 |
| --- | --- |
| `--dry-run` | リネームを実行せず、プレビューのみ表示する |
| `--recursive` | サブディレクトリも再帰的に処理する |
| `--verbose` | Annict側の詳細情報(作品・エピソード・放送情報)を表示する |
| `--no-cache` | ローカルキャッシュを使用しない |
| `--confidence` | 自動リネームに必要な最低信頼度(0〜100)。省略時は通常実行・`--dry-run` ともに90 |
| `--output` | 出力先ディレクトリ(省略時は入力ファイルと同じ場所) |
| `--epgstation-url` | 日付のみの録画を補完するEPGStationのURL。環境変数または `.env` の `EPGSTATION_URL` でも設定可能 |

対応する拡張子は `.mp4` `.ts` `.m2ts` `.mkv` `.m4v` です。

### リネーム後のファイル名

```
<出力先>/<作品名>/<作品名> #<話数> 「<サブタイトル>」.<元の拡張子>
```

元ファイルのコンテナ形式は変換せず、拡張子をそのまま維持します。Annict側にサブタイトルが登録されていない場合は、ファイル名から解析したサブタイトルを使用します。ファイルシステムで使用できない文字(`/ \ : * ? " < > |`)は全角の類似文字に置き換えられます。

話数を一意に決められない結合録画(` #01,02 `など)や小数話は、先頭の整数だけを採用せずスキップします。話数のない特番・総集編や第0話はスキップし、処理結果の`Skipped`に集計します。通常回らしいファイルに作品名と録画日だけがある場合は、Annictの`syobocalTid`を使ってしょぼいカレンダーの放送履歴を照合します。同じ日に得られた有効な候補がすべて同じ正整数話数を示し、その話数とサブタイトルがAnnictのちょうど1エピソードに対応するときだけリネームします。

話数がなくサブタイトルだけがある録画は、従来どおりサブタイトル全体で一意に決まる場合を先に照合します。それで決まらないときだけ録画日を使い、Annictの同名・明示的な続編候補ごとにしょぼいカレンダーを確認します。`/`または`／`で区切られた公式複合サブタイトルの完全な要素（または明示的な「ほか」省略）と一致し、放送話数も含めて成功する作品がちょうど1件で、未確認候補が残らない場合だけリネームします。単なる部分文字列、前編・後編の相違、API失敗、複数作品での成立はスキップします。

録画日があり、話数・サブタイトル・最終回指定のない `セレクション放送` / `セレクション再放送` は、末尾の放送枠名を除いて同じ厳密な日付照合を行います。選抜順から元の話数を推測しません。「ワールド イズ ダンシング」の `[終] 留〆` は話数に変換せず、サブタイトルでAnnictのエピソードを一意に確認します。

Annictの第2クール以降に `syobocalTid` が未登録でも、元作品と明示的なクール続編のエピソード一覧が全件揃い、話数が重複せず、元作品の放送表と話数・サブタイトル全体が一致する場合だけ補完します。別のシーズンや独立した放送表を持つ作品、字幕欠落、警告付きの放送行しかない場合には、この補完を使いません。

複数局で話数が異なる場合は、同じ処理対象に含まれる「録画日と明示話数があるファイル」を放送局アンカーとして使います。異なる録画日のアンカーが2件以上同じチャンネルを一意に示し、別チャンネルを示すアンカーが1件もない場合だけ、そのチャンネルに絞って日付のみの録画を判定します。アンカー不足や矛盾があれば推測せずスキップします。処理順への依存を避け、明示話数のファイルに宛先の優先権を与えるため、バッチ内では日付のみの候補を最後に処理します。

この照合では `https://cal.syoboi.jp/db.php` の `ProgLookup` を使用します。サービスの仕様に従って固有User-Agentを送信し、リクエスト間隔を1秒以上空け、結果を既定で7日間ローカルキャッシュします。`--no-cache`指定時はこのキャッシュも無効になります。

### EPGStationの録画履歴による補完

通常の日付照合で確定できない「作品名と録画日だけ」のファイルは、EPGStationに残る録画情報で放送局と時刻を補えます。任意の機能で、URLを設定した場合だけ利用します。

```sh
anime-renamer --dry-run --epgstation-url http://epgstation:8888 /recordings/

# 環境変数、または対象ディレクトリ・親ディレクトリの .env でも設定可能
export EPGSTATION_URL=http://epgstation:8888
anime-renamer --dry-run /recordings/
```

EPGStationから取得するのは `/api/recorded` と `/api/channels` の情報のみです。元ファイル名全体（拡張子を除く）と録画日が一致する履歴がちょうど1件ある場合だけ使います。`.m2ts` を `.mp4` に変換した録画にも対応しますが、作品名や日付だけが似た履歴、元ファイル名が変更済みの履歴からは推測しません。録画中・エンコード中、履歴の重複、途中ページの取得失敗も補完を停止します。検索結果と放送局一覧は実行中だけ保持し、EPGStation上の録画・設定・ファイルは変更しません。

取得した放送局名をしょぼいカレンダーの `ChLookup` と照合し、開始・終了時刻も一致する放送行に絞ります。番組説明の先頭に `第4話` / `Chapter.6` / `#6` などがあれば、その話数も放送表と照合し、字幕があればAnnictとの一致を求めます。あらすじ中に出てくる話数は採用しません。警告付き放送行は、EPGStationの明示話数・字幕でも裏付けられる場合だけ使用します。Annict側の作品・話数・字幕が一意に決まらない場合は、従来どおりスキップします。

## 仕組み

1. ファイル名を解析し、作品名・話数・サブタイトル・録画日時を抽出
2. Annict APIで作品名を検索
3. 該当する作品が複数見つかった場合、放送シーズン・話数などで絞り込み
4. 話数・サブタイトル・放送日時の一致度からマッチングの信頼度を算出
5. 話数がない通常回はしょぼいカレンダーの放送履歴とAnnictエピソードが一意に一致するか検証し、必要なら同じバッチの2件以上の一貫した放送局アンカーで絞り込み
6. 信頼度が閾値以上であればリネームを実行(閾値未満や一意に決まらないものはリネームしない)
