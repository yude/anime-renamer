# 耐障害性・例外処理の確認（2026-11-15）

`.anime-renamer-backups` を成功後も無条件に保持する旧動作は、一括処理の既定値として不適切だったため修正した。成功後は削除し、保持する場合は `--keep-backup` で明示する。失敗時の復旧可能性を保つため、削除は動画の検証・置き換え・ディレクトリ同期が完了した後に限定する。

## 発見事項と修正

| 問題 | 修正・主な回帰検証 |
| --- | --- |
| 正常終了でも元動画のバックアップが蓄積し、次回更新を妨げる | 成功後に当該バックアップと空ディレクトリを削除。旧バックアップは同じメタデータへの再実行時に内容を全検証してから削除。成功・再更新・保持指定・破損した旧バックアップをテスト |
| バックアップの検証・削除と別の埋め込みが競合し得る | 動画単位のOSファイルロックを追加。競合時は待ち続けずエラー。プロセス終了後に残るロックファイルの再利用を子プロセスで検証 |
| コピー中の元動画変更、更新日時・所有者・拡張属性の消失、新規フォルダの同期不足 | 元動画の同一性・サイズ・更新日時・モードを再確認。Linux/macOSで所有者・拡張属性も保持。コピー先と新規フォルダの親を同期してから元の名前を削除。変更注入・属性・長い名前の回帰テスト |
| NFOを直接作成すると通常の書き込み失敗で不完全なファイルが残る | 一時ファイルを同期してから上書きせず公開。リンク非対応環境のコピー失敗でも今回の不完全ファイルだけを削除。手書きNFOは保持 |
| フォルダの既存 `tvshow.nfo` が別のAnnict作品でもエピソードNFOを作成する | 書き込み前に作品IDを検証し、競合時は停止。NFO読み取り・生成のサイズも制限。dry-run内の共有NFOを予約し、重複プレビュー・競合を防止 |
| 一部候補のAPI取得失敗を候補の不在として扱い、一意に見える候補を選ぶ | 必要な候補の取得が失敗したら処理を中止。関連・特番候補はエピソード取得完了後にメモリキャッシュへ登録。不完全候補で動画を移動しないことと再試行を検証 |
| GraphQLの打ち切りやREST検索の先頭ページのみで照合する | `pageInfo.hasNextPage` を確認し、不完全な検索はページングするRESTへ切り替える。エピソードも全件取得し、重複・無効ID・上限超過を拒否。51作品の2ページ取得などをテスト |
| 同じ話数の複数エピソードから先頭を選ぶ・並び順だけでメタデータ話数を確定する | 字幕を含め一意に決まらなければ照合を保留。メタデータにはAnnictの明示話数を要求し、`sort_number` だけのものを拒否 |
| 外部コマンドの無期限待機・無制限の出力取得、待機中に中断できないAPI再試行 | 埋め込み1本あたり既定30分、stdout 8 MiB・stderr 16 KiB、パケットハッシュは逐次計算。ローカルプロトコルのみ許可。APIと子プロセスへ中断を伝搬し、キャンセルをNFO成功へ置き換えない。出力超過・タイムアウト・待機キャンセルを検証 |
| TS読み取りのI/Oエラーを情報欠落と混同する、整数変換やRetry-Afterのオーバーフロー | I/Oエラーを失敗として報告。整数変換前の上限確認、待機の上限設定を追加。破損・不正入力は既存の厳密な照合条件で保留 |
| 無効キャッシュの削除、相対パスでの親 `.env` 見落とし、実績表示の混同 | 無効キャッシュの `Clear` を無操作にし、設定探索を絶対パスから開始。移動と配置済みを分けて集計。依存ツール不在などは移動前に報告 |

FFmpegの出力上限テストでは、`bytes.Buffer` の埋め込みにより `io.Copy` が上限付き `Write` を迂回する問題も検出した。バッファを非公開フィールドにして、必ず上限を通るよう修正した。

## バックアップが残る場合

| 状態 | 動作 |
| --- | --- |
| 検証・置き換え・同期・後片付けが成功 | バックアップを削除。共有ディレクトリは空の場合だけ削除 |
| `--keep-backup` 指定 | 成功後も保持し、パスを表示 |
| 置き換え前の失敗 | 元動画を保持。バックアップ作成後の失敗なら、そのバックアップも保持 |
| 置き換え後の同期失敗 | 更新済み動画と復旧用バックアップを保持し、失敗を報告 |
| バックアップ削除の失敗 | 更新済み動画は保持し、削除失敗と残ったパスを報告 |
| 再実行時に未検証・不一致・破損バックアップがある | 自動削除せずエラー。同じメタデータで内容検証に通る既存バックアップだけを削除 |
| 強制終了・電源断 | バックアップ・一時ファイル・ロックファイルが残る可能性あり。ロックファイルは再利用可能。未知のデータを再帰削除する処理は設けない |

## 実行した検証と限界

- 全13パッケージの通常テスト・race検査、`go vet`、Staticcheck、整形・差分検査（全体の文カバレッジ81.7%）。カバレッジは全ての障害が再現できたことを意味しない。
- FFmpegを使うMP4/M4V/MKV、チャプター保持、パケットハッシュ、既存バックアップ再検証の統合テスト。
- コピー・バックアップ作成・置き換え・同期・削除の故障注入と、元データ／復旧データの保持確認。
- ファイル名解析・TS解析をそれぞれ10秒指定でfuzz検査（55,887件／352,308件、失敗なし）。
- Linux amd64/arm64、macOS amd64/arm64、Windows amd64のビルド確認。
- 生成した小さな動画と実際のAnnict APIを使用したCLI確認。複数階層の出力先への移動、既定でバックアップ・一時ファイル・ロックが残らないこと、保持指定と次回の検証付き削除、埋め込みタグ、削除だけの再実行で動画が変化しないことを確認。

実行時の検証環境はLinux。macOS/Windowsはビルド確認までで、Windowsのディレクトリ同期やACL・拡張属性の保持は同じ保証にならない。実際の電源断や全てのネットワークファイルシステムの障害は再現していない。リンク非対応時の排他的コピーは、強制終了で不完全な公開先が残る場合があるため、原本を削除する前に同期完了を要求する。

バッチ全体、およびリネームとメタデータ付与をまとめた単一トランザクションではない。後段の失敗で移動済み・作成済みのファイルがある場合は、エラーと結果に反映する。協調しない録画・変換・移動ソフトの書き込みをOSロックだけで禁止することはできない。ファイル状態の再確認は行うが、同一サイズ・同一時刻に戻す外部変更などを完全には検出できない。

外部データベースの内容の正しさを保証する調査でもない。候補の欠落・矛盾・曖昧さを検出した場合は処理を保留する方針を維持した。本番録画の更新、Jellyfinの設定変更・スキャン・画面での反映確認は今回実行していない。

## 追補: FFmpeg 7.1.5のHEVCヘッダー正規化

「綺麗にしてもらえますか。」第1話で、FFmpeg 7.1.5がMP4の `hvcC` の `parallelismType` を1から0へ変更する挙動を再現した。元の録画は `min_spatial_segmentation_idc=0` で、この項目が並列処理の制約を課さない条件だった。映像107,992パケット・音声84,438パケットの内容・時刻はすべて一致し、119バイトの初期化ヘッダーのうち変わったのはこの1バイトだけだった。FFmpeg 6.1.1では同じ変更が発生せず、従来の検証ではこのバージョン差をカバーできていなかった。

修正では、トラックIDとMP4のボックス構造から対象のサンプル記述を特定し、ほかの初期化情報が完全に同じ場合だけ一時MP4の当該バイトを元に戻す。その後は従来のヘッダー・全パケット・時刻の完全一致検証を行う。複数のサンプル記述、曖昧・破損した構造、意味のあるほかのヘッダー変更は拒否する。仕様上の条件は [FFmpeg 7.1.5の `hvcc_write`](https://github.com/FFmpeg/FFmpeg/blob/n7.1.5/libavformat/hevc.c#L786-L792) でも確認できる。

両バージョンで全13パッケージのrace検査とHEVCの回帰テストを実行した。VPSなどの別項目の変更やパケット破損を拒否すること、元動画を変更しないことも確認した。CIにはDebian 13のFFmpeg 7でのテストを追加した。

対象録画のローカルコピー（980,845,469バイト）と実際のAnnict APIでもCLIを検証し、既存の生成済みNFOを保持して埋め込みに成功した。全192,430パケットと初期化ヘッダーの完全一致、成功後にバックアップ・一時ファイル・ロックが残らないことを確認し、検証用動画は削除した。本番録画は変更していない。
